# Test Coverage and Traceability

Every function in the built sources is listed below with the evidence that
verifies it. The project is organised in three verification tiers:

| Tier | Meaning | How to run |
|------|---------|------------|
| **U** | Unit tested in isolation: no network, no live toxcore state, time injected where relevant. | `make test` |
| **I** | Integration tested with an *offline* toxcore instance (`tox_new()` with UDP, IPv6 and LAN discovery disabled) or by exercising the real code path through the tiers below it. | `make test` |
| **J** | Justified as not independently unit testable. The reason is stated per function. These are the composition roots and the toxcore callback entry points. | — |

All suites are additionally run under AddressSanitizer and
UndefinedBehaviorSanitizer: `make test-sanitize`.

## mq_persist.c — `tests/test_mq_persist.c`

The durable queue mirror is verified against the **real** delivery queue and the
**real** file format: the test enqueues into `msg_queue`, saves, wipes the queue
with `mq_init()` and loads the file back, so both directions are observed on
real data. Files are written byte by byte inside a `mkdtemp()` directory, which
lets every rejection path be exercised with a precisely malformed input.

| Function | Tier | Test |
|----------|------|------|
| `mq_persist_save` | U | T1, T3, T3b, T4 (round trip, atomic replace, nested directory, empty queue) |
| `mq_persist_load` | U | T1–T10 |
| `le_put_u32` `le_put_i32` `le_get_u32` `le_get_i32` | U | exercised by every round trip; the corruption cases pin the byte order |
| `mq_sync_parent_dir` | U | T1, T3, T3b (a bare file name, the working directory and a subdirectory) |
| `mq_save_visit` `mq_read_all` `mq_validate_records` | U | internal helpers exercised by every save and load |

Scenarios: 1. round trip in FIFO order 2. path validation (NULL, empty,
missing, unwritable directory) 3. atomic replace with no leftover `.tmp`
3b. a target inside a subdirectory, which also exercises the directory flush
4. empty queue 5. binary and maximal-size payload fidelity 6. corrupt file
rejected without touching the live queue (bad magic, unknown version, short
file) 7. invalid records rejected before any import (truncation, zero and
oversized length, negative friend number, absurd count) 8. full queue refuses
the restore 9. restart delivers the restored queue in order with a fresh attempt
budget 10. the change hook fires only on real changes.

## toxrelayer.c — the composition root

`toxrelayer.c` owns the process: it creates the Tox instance, registers the toxcore
callbacks and runs the event loop. Most of it cannot be unit tested without a
live DHT, and forcing it to be would mean rewriting the toxcore event contract.
The functions that were independently testable were **moved out** of this file
during the remediation — the protocol, the queue, the database and the command
parser now live in their own tested modules, which is why this list is short.

| Function | Tier | Basis |
|----------|------|-------|
| `relay_resolve_peer` `relay_peer_key` `relay_peer_is_metacom` `relay_tracker` `relay_channel_known` | I | adapters from the relay environment onto the peer directory and the tracker array; the policy that consumes them is unit tested in `test_relay.c` |
| `relay_store` `relay_enqueue` `relay_fetch_range` `relay_remember_serial` | I | adapters onto `msg_database_add`, `mq_enqueue`, `msg_database_range` and `ini_puts`; each target is unit tested |
| `relay_init` `relay_last_stored_sn` `relay_log_outcome` | I | wiring and presentation of an outcome that `test_relay.c` verifies |
| `tox_transport` | I | the queue-side contract is fully tested (`test_msg_queue.c`); this is the adapter, exercised through `mq_service` |
| `execute` | I | covered by `test_commands.c` |
| `save_data` `load_tox` | J | file plus toxcore serialisation; the leak-free paths are verified by inspection against the static analyser and by the failure-path tests of `misc.c`'s file helpers |
| `purge_empty_groups` `purge_inactive_friends` `check_group_purge` | I | the table operations they call are unit tested (`test_groupchats.c`) |

| `print_usage` `print_profile_info` `welcom_logo_metaCom` `local_info_display` `local_node_info_display` `receipt_display` | J | console formatting of live state |
| `console_key_available` `get_token` `evaluate_input` `legacy_data_file_rename` `init_toxrelayer_state` | J | interactive console and one-shot start-up helpers |

Queue persistence is wired here but not implemented here: `main()` calls
`mq_persist_load()` once at start-up and `exit_toxrelayer()` calls
`mq_persist_save()`. The flush trigger is `on_queue_changed()`, registered
through the tested `mq_set_change_hook()`. Every one of those three functions
(`mq_persist_load`, `mq_persist_save`, `mq_set_change_hook`) is unit tested in
`test_mq_persist.c`, so this file only supplies the file name and the timing.

The relay policy that used to live in this file — `handle_local_telegram`,
`handle_text_telegram`, `handle_cmd_telegram`, `request_missed_telegrams` and
`recover_receive_serial_numbers` — has been **moved into `relay.c`**, where it is
unit tested. What remains here are the adapters that bind it to toxcore.

The intent is that this list shrinks over time: any logic worth testing should
move into a module rather than stay in the composition root.

## How to reproduce

```sh
make                 # build: 0 errors, 0 warnings (-Wall -Wextra -Werror)
make test            # all 10 suites
make test-sanitize   # the same suites under ASan + UBSan
make analyze         # clang static analyzer + clang-tidy: 0 findings
make analyze-strict  # the gate that fails on any new finding
```

## Adding a test

1. Put the suite in `tests/test_<module>.c` and keep it self-contained: no
   network, no real files outside a `mkdtemp()` directory, time injected rather
   than slept on.
2. Register it in the `Makefile` under `TEST_BINS` with the modules it needs in
   `EXTRA_SRC` and, when toxcore is required, `EXTRA_LIBS = $(LDFLAGS)`.
3. Add the function to the table above with the test identifiers that cover it.
4. Run `make test-sanitize` and `make analyze-strict` before committing.
